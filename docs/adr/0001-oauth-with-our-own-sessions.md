# Log in with OAuth, sessions built ourselves

Site accounts are created only by logging in with Google (OAuth), and the site issues and stores its own sessions: a random session ID in an `HttpOnly`, `Secure`, `SameSite` cookie, backed by a row in D1 that lasts 30 days, renews when it is used, and is deleted on logout. We never store passwords, which removes the riskiest part of auth (hashing, resets, sending email). We chose not to use a hosted auth service (Clerk, Auth0, Supabase Auth) because this site is a learning project and the session layer is exactly the part worth understanding. A small library may handle the provider-specific OAuth details. Production and development use separate Google OAuth clients. The dev client is registered for localhost and for the preview alias (`<branch>.jetysalina-com.pages.dev`) of each branch that needs login, added when that branch starts; other preview branches have no working login. We chose this over a single long-lived `preview` branch because adding a redirect URI now and then is cheaper than merging or force-pushing a feature branch onto `preview` every time login needs testing.
